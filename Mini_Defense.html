Q1: 你的 Test set 要模擬哪一種 Unknown？
我的 Test set 要模擬「全新 YouTube 視訊片段、未見過的地理空域、以及不同無人機相機感測器的泛化能力（Unseen Video Clips & Novel Aerial Scenes）」。在實際部署情境中，無人機永遠是在全新的道路或空域執行巡航，因此 Test set 必須是模型在訓練期間完全未曾看過的新影片來源。
Q2: 為什麼選擇目前的 Split Strategy？
我選擇「Group Split by video_id（依 YouTube 來源視訊切分）」，嚴格禁止 Random Split。因為無人機航拍是每秒 30 幀的連續視訊串流，相鄰影格間隔僅 0.03 秒，背景地形與車輛位置幾乎一模一樣。如果使用隨機打散（Random Split），測試集與訓練集將高度共享相同的道路背景，產生嚴重的時空序列資訊洩漏（Temporal Split Leakage），評測分數會虛假高估。依據 video_id 徹底隔開，才能確保測試集是真實的未知評估。
Q3: 你的 Dataset 中最可能造成 Leakage 的欄位或資料流程是什麼？
最可能造成 Leakage 的環節有兩個：
  1. 資料流程上的 Split Leakage：同一支 YouTube 視訊的影格跨集合洩漏，讓模型背下靜態路面熱特徵。
  2. 影像畫面上的 Shortcut Leakage（捷徑學習）：YouTube 視訊角落常帶有固定的頻道浮水印（Logo）或飛控 OSD 儀表。如果車輛常出現在某些特定相對位置，模型可能會將浮水印當成預測線索，因此必須在前處理將邊緣裁切遮罩。
Q4: 目前 Dataset 最重要的 Coverage Limitation 是什麼？
目前最大的限制是「缺乏原生 14-bit 輻射溫度數據（Radiometric Data）與無人機實機飛行高度」。因為資料來源是 YouTube 經過二次編碼壓縮的 8-bit 視訊，已經丟失了熱像儀直出的真實物理攝氏溫度，且無法取得精確高度將像素長寬換算成公尺。因此本模型只能根據相對明暗的熱特徵進行辨識，無法宣稱具備以「實體溫度門檻」過濾虛警的能力。
